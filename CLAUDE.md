# container-sec-derive

Runtime tool that derives minimum container security config by observing a running container via eBPF (wraps Inspektor Gadget). Go 1.26+, MIT, one-shot CLI. Binary: `csd`. **v0.7.0 released** (v0.6.0 was the last new observer; v0.7.0 = maintenance/consumption — `--runtime podman`, compose-lint-profile→catalog reconcile, live digest-pin fix). Observer history: — v0.1 shipped the capability observer (signed binaries + private GHCR image); v0.2 added the read-only-filesystem + tmpfs observer (`--observe fs`). v0.3 added privileged-mode decomposition (`--observe devices` + `--observe privileged`); v0.3.1 flags that decomposition as partial (the AppArmor/seccomp `security_opt` dimension stays unobserved). **v0.4.0 adds the dangerous-`cap_add` validator (`--observe capadd`, ROADMAP §v0.5, CL-0011)** — pulled ahead of the ROADMAP §v0.4 Docker-socket observer, which is **deferred/signal-blocked** (no built-in IG gadget for AF_UNIX/HTTP at the pin; issue #110). Release numbering stays sequential (v0.4.0); ROADMAP phase labels are planning order, not release tags. **v0.4.1** is a maintenance release hardening the #120 deep-review findings (`0600` evidence sidecar, stricter `cap_add` validation, faithful `compose-patch` line I/O, tighter drop-rate + target-selection accounting; strictly more conservative, no schema change — `ToolVersion = 0.4.1`, `schema_version` stays 1.3). **v0.8 network-egress observer (`--observe egress`, ROADMAP §v0.8, issue #136) SHIPPED as v0.5.0 (2026-06-18)**: `trace_tcp` → minimum outbound allowlist, with `--format nftables` + `--format k8s-networkpolicy` enforcement output (schema bumped to 1.4). **v0.6.0 (2026-06-18) adds the egress DNS/hostname follow-up** (issue #159): `trace_dns` as a 2nd signal (`--dns-fixture` + live two-gadget path concurrent with `trace_tcp`) → per-destination `hostnames` + a `dns_resolvers` block (the UDP/53 resolver a default-DROP allowlist must permit), rendered in nftables/NetworkPolicy; schema bumped to **1.5**.

## Architecture (forward-compat — PLAN.md §Architecture)

Four layers: **Observer → Attribution → Aggregator → Formatter**. v1 ships exactly one observer (`cap_capable`). Future observers (read_only paths, devices, sockets, egress) plug into this same interface. Don't collapse the layering to ship a second observer faster — it is load-bearing for v0.2+.

Confidence rubric (high/moderate/low) is csd's analog of severity. Rubric definition lives in PLAN.md §Confidence scoring — don't restate it elsewhere; update PLAN.md and reference.

## Privilege posture

csd runs with `CAP_BPF` + `CAP_PERFMON` + `--pid=host` + container-runtime socket. Root-equivalent on the host. Every new dep, every new command surface, every formatter, lands under that blast radius. PLAN.md §Tool posture has the full threat model.

## IG integration

Subprocess, not library (Decisions item 5). IG schema is pinned per release via `PINNED_IG_VERSION` / `MIN_IG_VERSION` / `MAX_TESTED_IG_VERSION` plus per-version fixtures under `testdata/ig-versions/<version>/`. Bumping the pin means: add a new version directory, regenerate sample NDJSON, re-run reference-image smoke, commit. Do **not** patch the parser to cope with schema drift across pinned versions.

## Quality checks

`go vet ./...`, `go test ./...`, `go build -o csd ./cmd/csd`. All must pass.

**The full test-tier map — what each tier proves and where it runs (hermetic vs
live vs real-host) — is `docs/testing.md`.** Read it before reasoning about
coverage: the hermetic core (unit + golden + `--fixture` pipeline) is fully
runnable without a kernel and is the bulk of the suite; the live-BPF half and the
closed-loop "meets intent" proof need a real host, and the plan to close those
gaps is tracked in **issue #116**.

Live-BPF CI (`.github/workflows/integration.yml`) gates PRs beyond the unit
suite, **trimmed for Actions cost** (2026-06-19; see `docs/testing.md`). The
smoke scripts — `smoke_wsl2.sh` (caps),
`smoke_fs.sh`, `smoke_device.sh`, `smoke_capadd.sh`, `smoke_egress.sh` (incl. the
DNS leg) — all share the synthetic exerciser as the **deterministic hard gate**;
the postgres/caddy/tailscale reference images are informational (they can
legitimately observe zero post-attach events, `docs/known-deltas.md`). Cadence:
- **Per-PR** (the `smoke` job, keyed on `github.event_name`): **amd64 only,
  synthetic-only (`SMOKE_ONLY=synthetic`), 10s window** (closed-loop 15s). The
  deterministic gates fire within ~1-2s of attach (500ms init-window), so 10s is
  ample; ~1.5-2 min vs the old ~6.5 min.
- **Every-3-days `schedule` + `workflow_dispatch`**: the **full reference set at
  30s**, plus a **native `ubuntu-24.04-arm` leg** (runner matrix) that runs the
  synthetic gates lean (synthetic-only/10s, closed-loop skipped — arch-agnostic)
  to prove the eBPF attach/parse path on arm64, since we ship arm64 artifacts. A
  dispatch `duration` input overrides the window. `ig` install is per-arch.
- The kretprobe miss-rate measurement (`scripts/kretprobe_missrate.sh`,
  `make missrate`) and the bisection job are `workflow_dispatch`-only.

The smoke job posts an allowlisted, secrets-free result comment on the PR
(grep `^(PASS|FAIL|INFO|smoke-<x>:)` — prefix diagnostics with `INFO` to surface
them, since the Actions log API is unreadable from the container). **CodeQL is
on an every-3-days schedule + `workflow_dispatch` (TEMPORARY, #165 — restore the
per-PR trigger when development slows), not per-PR.** Locally: `make smoke-wsl2`,
`make missrate` (need docker + pinned `ig` + root — see `docs/dev-setup.md`).

## Commit & PR workflow

- One logical change per commit. Imperative subject ≤72 chars. No Conventional Commits prefixes.
- All commits SSH-signed. Verify: `git log --format='%h %G? %s'` — every commit shows `G`.
- All changes via PR, squash-merge to main.
- **Update the docs your change touches in the same PR**, so the entry-point docs never trail `main`: keep the CLAUDE.md status section current, update the PLAN.md build order, tick PLAN.md success-criteria boxes (only with evidence, never on intent), and bump ROADMAP if a phase moved. Don't reference uncommitted/ephemeral files from committed prose.
- **Add a `CHANGELOG.md` `[Unreleased]` entry for any version-visible change** (new observer/formatter/flag, behavior change, schema bump, security fix). Format is [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) — group under `Added`/`Changed`/`Fixed`/`Removed`/`Security`. Pure refactors, test-only, and internal-doc PRs don't need an entry. The release process versions the `[Unreleased]` section; see `docs/RELEASING.md`.

## Dependency pinning

- **GitHub Actions**: SHA-pin every `uses:` (including first-party), tag in trailing comment. Only exception: `uses: ./`.
- **Go runtime deps**: stdlib-first. Any third-party runtime dep requires discussion — this binary runs root-equivalent. **One accepted non-stdlib `go.mod` require: `github.com/AdamKorcz/go-118-fuzz-build` (+ its `go-fuzz-headers` indirect)** — the ClusterFuzzLite Go fuzz shim (#174). It is **fuzz-build-only**: retained in `go.mod` solely by `internal/fuzzdep/fuzzdep.go` behind the never-set `fuzzdep` build tag, so it is **never linked into the `csd` binary** (verify: `go list -deps ./cmd/csd | grep go-118` is empty). Don't `go mod tidy` it away, and don't treat it as a runtime dep.
- **Vendored `ig` binary**: pinned to a specific upstream release SHA, cosign-verified at release time (PLAN.md §Supply-chain). No "latest" anywhere in the release path.
- **Docker base images** (when added): digest-pin.

## Publishing

Signed release artifacts only — static binaries (`csd_linux_amd64`, `csd_linux_arm64`) and the container image **`ghcr.io/tmatens/container-sec-derive`** (GHCR; auth via the ephemeral `GITHUB_TOKEN`, no Docker Hub secret). **Cosign signing is key-based with `--tlog-upload=false`** (NOT keyless) — nothing is written to the public Rekor log while the project is unpublished. Needs repo secrets `COSIGN_PRIVATE_KEY` + `COSIGN_PASSWORD` and a committed `cosign.pub` (`cosign generate-key-pair`); verify offline with `cosign verify-blob --key cosign.pub --insecure-ignore-tlog …`. Binaries get detached `<file>.sig`; the image manifest is cosign-signed and carries SBOM + OpenVEX attestations, with a scheduled Docker Scout scan (`scout-scan.yml`) consuming the same VEX. No manual uploads. **COI posture (per maintainer): private publishing is fine; only PUBLIC exposure is gated.** The GHCR image publishes **private** (collaborator-only, private by default) with no public footprint; the sole COI-gated act is flipping the GHCR package visibility to public — done after the COI decision (no in-workflow approval gate). csd ships to GHCR, not Docker Hub like sibling compose-lint, for the private-by-default + no-extra-secret path; dual-publishing compose-lint to GHCR is a possible later follow-up. When the project goes public, switching cosign back to keyless (OIDC + Rekor) is a deliberate, reviewable change.

## Things to avoid

- No AI authorship attribution (no `Co-Authored-By` for AI, no "Generated by" notices, no "built with AI" badges).
- No runtime deps beyond the Go stdlib without discussion (the one accepted `go.mod` require — `go-118-fuzz-build`, fuzz-build-only, never linked into the binary — is noted under Dependency pinning).
- No direct `ig` Go library imports — subprocess only.
- No second observer before v0.1 ships (Decisions item 8).
- No parser workarounds for IG schema drift; bump the pin and regenerate fixtures instead.
- No mutable refs in CI.
- No `cmd | tee log` as the gating command in a CI step — the pipeline's exit
  becomes `tee`'s `0`, so a real failure passes green (pipefail is not reliably
  in effect for `run:` steps). Capture the exit code: `cmd > log 2>&1 && rc=0 || rc=$?; cat log; exit $rc`.
- No private/internal tooling references in a public repo.
- No restating of PLAN.md content here — link to the section and keep CLAUDE.md tight.
